# 라운지핏 회원·수업 예약 플랫폼 PRD v1.0

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 라운지핏 회원·수업 예약 플랫폼 |
| 고객사 | 라운지핏 (필라테스·요가 스튜디오 체인, 3개 지점) |
| 작성 근거 | 정유나 운영이사 상담 4라운드 (요구사항 정리서 v2) |
| 개발 구축비 | 2,000만 원 (순수 1차 구축비, 운영비 별도) |
| 개발 기간 | 약 2개월 |
| 문서 상태 | 개발 착수본 |

---

## 1. 배경 및 목적

### 1.1 문제 정의

라운지핏은 3개 지점, 회원 약 1,200명 규모로 운영 중이나 예약 접수는 카톡·전화, 이용권 관리는 지점별 엑셀에 의존하고 있다. 이로 인해 다음 세 가지 문제가 반복 발생한다.

1. **중복 예약** — 인기 시간대에 요청이 몰릴 때, 그리고 한 매니저가 응대하는 사이 다른 매니저가 같은 시간을 접수할 때 발생한다. 고객이 지목한 최우선 병목이다.
2. **노쇼** — 사전 취소 없이 불참해도 제재 수단이 없으며, 빈자리를 다른 회원에게 넘길 경로도 없다.
3. **정산 오류** — 횟수제 이용권 잔여를 수기로 세는 과정에서 오차가 누적된다.

### 1.2 해결 방향

회원이 실시간 잔여 좌석을 직접 확인하고 예약하는 구조로 전환한다. 좌석 확정을 시스템 단일 지점에서 처리하여 중복을 원천 차단하고, 대기열로 취소 좌석을 회수하며, 이용권 차감을 자동화한다.

### 1.3 성공 기준

- 오픈 후 앱 경유 예약에서 중복 예약 0건
- 이용권 잔여 횟수의 시스템 값과 실제 수강 이력 간 불일치 0건
- 정량 목표(노쇼율 감소폭 등)는 고객이 제시하지 않았으므로 본 PRD에서 설정하지 않는다

## 2. 범위

### 2.1 포함 (1차)

이미 이용권을 보유한 회원의 **예약 · 취소 · 횟수 차감 · 대기열**과, 이를 운영하기 위한 관리자 백오피스.

### 2.2 제외 (2차 고도화 — 고객 확정)

| 항목 | 1차 대체 운영 |
|---|---|
| 앱 내 신규 이용권 결제 | 기존 오프라인 결제 유지 |
| 태블릿 현장 출석 체크 | 데스크 매니저 수기 확인 후 관리자 페이지 처리 |
| 강사 전용 화면·권한 | 매니저가 카톡 캡처 전달 또는 데스크 PC 공유 |
| 회원 셀프 홀딩 신청·기간 자동 연장 | 매니저 수기 처리 |
| 노쇼 누적 자동 정지·자동 해제 | 매니저 수동 스위치 |

> 태블릿 출석 체크는 2차로 이관되었으나 입력 방식(휴대폰 뒷 4자리)이 이미 합의되었다. 1차 데이터 모델 설계 시 회원 식별 키로 뒷 4자리 조회를 고려해 둔다.

## 3. 사용자 및 권한

| 역할 | 규모 | 1차 계정 | 주요 동선 |
|---|---|---|---|
| 회원 | 약 1,200명 | O | 시간표 조회, 예약·취소, 대기 등록·확정 |
| 지점 매니저 | 3개 지점 | O | 시간표 등록, 대리 예약, 출석·노쇼 처리, 폐강, 예약 정지 |
| 중앙 관리자 | 1명 | O | 정책값 설정, 전 지점 통계 |
| 강사 | — | X | (1차 미제공) |

### 3.1 권한 규칙

- 지점 매니저는 **자기 지점의 시간표·회원만** 열람·수정한다.
- **예외**: 자기 지점 수업을 예약한 타 지점 회원은 예약 내역 조회 및 출석·노쇼 처리가 가능하다. 교차 수강을 허용하므로 이 예외가 없으면 현장 처리가 불가능하다.
- 타 지점 회원 노출 범위는 **이름 + 휴대폰 뒷 4자리 + 잔여 횟수**로 제한한다. 전체 연락처, 주소, 결제 이력은 노출하지 않는다.
- 중앙 관리자는 3개 지점 전체를 열람하며, 정책값 설정 화면은 중앙 관리자 전용이다.

## 4. 도메인 모델

### 4.1 핵심 엔티티

```
Branch(지점)          : 3건 고정
Member(회원)          : 소속 지점, 휴대폰, 예약정지 상태
TicketType(수강권종류) : 1:1 개인레슨 / 1:4 기구 필라테스 / 요가 전용
Ticket(이용권)        : 회원 보유, 총 횟수, 만료일, 일·주 한도
ClassSchedule(수업)    : 지점, 수강권종류, 강사, 시작시각, 정원
Reservation(예약)      : 회원-수업, 상태
WaitlistEntry(대기)    : 회원-수업, 순번, 상태
TicketUsage(횟수원장)  : 이용권 차감·복구의 단일 원장
NoShowRecord(노쇼이력) : 누적 카운트 산출용
PolicySetting(정책값)  : 관리자 설정 항목
NotificationLog(발송)  : 알림 발송 이력
```

### 4.2 횟수 관리 원칙

**이용권 잔여 횟수는 컬럼에 직접 증감하지 않는다.** `TicketUsage` 원장에 상태를 기록하고 잔여 횟수는 파생값으로 계산한다.

```
잔여 = 총 횟수 - COUNT(status IN (HOLD, CONFIRMED, CONSUMED))
```

| TicketUsage.status | 의미 |
|---|---|
| HOLD | 대기 등록으로 선점된 상태 |
| CONFIRMED | 예약 확정, 수업 미종료 |
| CONSUMED | 수강 완료 또는 노쇼로 소진 확정 |
| RELEASED | 취소·타임아웃·폐강으로 반환됨 |

숫자 필드를 직접 더하고 빼면 대기열 타임아웃과 폐강이 동시에 발생하는 경우 중복 복구 또는 유실이 발생한다. 원장 방식은 감사 추적도 함께 확보한다.

### 4.3 상태 전이

**Reservation**

```
RESERVED ─┬─→ CANCELED        (마감 전 취소, 횟수 복구)
          ├─→ LATE_CANCELED   (마감 후 취소, 차감 유지 / 노쇼 카운트 제외)
          ├─→ ATTENDED        (출석 처리)
          ├─→ NO_SHOW         (미출석 처리, 차감 유지 + 노쇼 카운트)
          └─→ CLASS_CANCELED  (폐강·스튜디오 취소, 횟수 복구)
```

**WaitlistEntry**

```
WAITING ─→ OFFERED ─┬─→ CONFIRMED  (기한 내 확정 → Reservation 생성)
                    └─→ EXPIRED    (타임아웃 → 다음 순번으로 이관)
WAITING ─┬─→ RELEASED (자진 취소 / 수업 시작 / 폐강)
```

## 5. 핵심 로직 명세

### 5.1 예약 생성

동시 요청 하에서도 정원을 초과하지 않아야 한다.

**검증 순서**

1. 회원 예약 정지 상태 확인
2. 보유 이용권의 수강권 종류와 수업 종류 일치 확인
3. 이용권 만료일 > 수업 시작 시각 확인
4. 잔여 횟수 ≥ 1 확인
5. 일·주 예약 한도 미초과 확인 (기준: 수업 일자, 주 = 월~일)
6. 동일 수업 중복 예약 여부 확인
7. 잔여 좌석 확인 후 확정

**동시성 처리**

- 좌석 확인과 확정은 단일 트랜잭션으로 처리하며, `ClassSchedule` 행에 배타 잠금을 건다.
- `Reservation(schedule_id, member_id)`에 유니크 제약을 두어 애플리케이션 로직 누락 시에도 중복을 막는다.
- 정원 초과 시 롤백하고 대기 등록을 안내한다.

### 5.2 대기열

**등록 시점 선차감을 채택한다.** 대기 등록과 동시에 `TicketUsage(HOLD)`를 생성하며, 잔여 횟수가 없으면 대기 등록 자체가 불가능하다.

> 설계 근거: 확정 시점 차감 방식은 한도를 소진한 회원이 대기 확정 순간에 기존 예약을 포기하는 복합 동선을 요구한다. 취소와 확정을 원자적으로 처리해야 하고 30분 타이머와 얽혀 CS 리스크가 크다. 선차감은 이 경로 자체를 제거한다. 대기 3건을 걸면 주 한도 3회가 전부 묶이며, 이는 무분별한 대기 등록을 억제하는 장치로 기능한다.

**빈자리 발생 시 처리**

1. 좌석 반환 → 대기열 1순위 조회
2. 심야 정지 구간(23:00~07:00)이면 배정을 보류하고 07:00에 재개
3. 1순위에게만 `OFFERED` 부여 후 알림 발송 (동시 다중 발송 금지, 순차 타이머)
4. 타임아웃 내 미확정 시 `EXPIRED` 처리 + HOLD 반환 → 다음 순번으로 이관

**타임아웃 분기**

| 조건 | 타임아웃 |
|---|---|
| 수업 시작까지 3시간 초과 | 30분 |
| 수업 시작까지 3시간 이내 | 10분 |

임박 수업에 자동 확정을 적용하지 않는 이유는, 회원이 인지하지 못한 상태에서 예약이 잡혀 노쇼로 이어지는 것을 막기 위함이다. 고객이 직접 확인한 방향이다.

**HOLD 반환 트리거**

| 트리거 | 처리 |
|---|---|
| 회원 자진 대기 취소 | 즉시 RELEASED |
| OFFERED 타임아웃 | 즉시 RELEASED + 다음 순번 이관 |
| 수업 시작 시각 도달 | 잔여 WAITING 전원 RELEASED |
| 폐강 / 스튜디오 당일 취소 | 예약자 복구와 함께 대기자 전원 RELEASED |
| 대기 확정 성공 | 반환 없음. HOLD → CONFIRMED 상태 전이 |

### 5.3 취소 및 페널티

| 구분 | 시점 | 횟수 | 노쇼 카운트 |
|---|---|---|---|
| 정상 취소 | 마감 시각 이전 | 복구 | 미적립 |
| 지각 취소 | 마감 시각 이후 | 차감 유지 | **미적립** |
| 무단 노쇼 | 미출석 | 차감 유지 | **적립** |
| 폐강·스튜디오 취소 | — | 복구 | 미적립 |

- 기본 마감 시각은 수업 시작 3시간 전이다.
- 노쇼 카운트가 임계값에 도달하면 관리자 페이지에 경고를 표시하고, **매니저가 수동으로 예약 정지 스위치를 조작**한다. 자동 판정·자동 해제는 2차 범위이다.
- 카운트는 설정된 주기(초기값 월간, 매월 1일)에 초기화한다.

**예약 정지 회원의 처리**

- 신규 예약 및 대기 등록: 차단
- 기존 예약: 유지
- 기존 예약의 본인 취소: **허용**

정지 회원의 취소까지 막으면 빈자리가 회수되지 않아 또 다른 노쇼를 낳는다.

### 5.4 폐강

- 매니저가 수업 시작 2시간 전 기준으로 판단하고 관리자 페이지에서 폐강 버튼을 누른다. 자동 폐강은 없다.
- 최소 진행 인원 미달 시 관리자 목록에 대상 수업을 강조 표시한다.
- 폐강 실행 시: 예약자 전원 `CLASS_CANCELED` + 횟수 복구, 대기자 전원 `RELEASED` + HOLD 복구, 양측에 알림 발송.

**설정값 검증**: 취소 마감(3시간)이 폐강 기준(2시간)보다 짧아지면 폐강 확정 후 취소가 들어와 인원이 다시 흔들린다. 정책값 저장 시 `취소 마감 ≥ 폐강 기준`을 검증하고 위반 시 차단한다.

### 5.5 롤링 오픈

매일 00:00에 **정확히 2주 뒤 하루치** 스케줄만 예약 가능 상태로 전환한다. 월 1회 일괄 오픈 구조에서 발생하던 오픈런 트래픽을 일 단위로 분산하는 것이 목적이다. 관리자는 여전히 월 단위로 시간표를 사전 등록하며, 등록과 오픈 노출은 분리된다.

### 5.6 대리 예약

병행 운영 기간 중 전화·카톡으로 들어오는 예약 요청은 **전량 대리 예약 기능으로 흡수한다.** 별도 접수 경로를 남기지 않는다. 남길 경우 이중 입력으로 중복 예약이 재발한다.

- 매니저가 회원 검색 후 대신 예약·취소한다.
- 검증 로직은 회원 직접 예약과 동일하게 적용한다.
- 처리자 계정을 예약 레코드에 기록한다.

## 7. 정책 설정값

### 7.1 관리자 설정 항목 (전 지점 공통)

지점별 차등 적용은 하지 않는다. 고객이 "모든 지점 동일 규정이 관리하기 수월하다"고 확정한 사항이다.

| 구분 | 항목 | 초기값 |
|---|---|---|
| 예약 | 취소 마감 시간 | 수업 시작 3시간 전 |
| 예약 | 롤링 오픈 기준 기간 | 2주 |
| 예약 | 롤링 오픈 실행 시각 | 00:00 |
| 대기열 | 기본 확정 타임아웃 | 30분 |
| 대기열 | 임박 수업 단축 타임아웃 | 10분 |
| 대기열 | 단축 적용 임계 | 수업 시작 3시간 전 이내 |
| 대기열 | 심야 정지 시작 | 23:00 |
| 대기열 | 심야 정지 종료 | 07:00 |
| 폐강 | 폐강 판단 기준 시각 | 수업 시작 2시간 전 |
| 폐강 | 최소 진행 인원 | 3명 |
| 페널티 | 노쇼 누적 임계 | 3회 |
| 페널티 | 정지 일수 | 7일 |
| 페널티 | 카운트 초기화 주기 | 월간 (매월 1일) |
| 운영 | 대리 예약 허용 여부 | ON |

**저장 시 검증 규칙**

- 취소 마감 ≥ 폐강 기준 시각
- 대기열 단축 임계 ≥ 폐강 기준 시각
- 심야 정지 시작 ≠ 종료
- 모든 시간 항목은 분 단위 정수

### 7.2 코드 고정 항목 (설정 불가)

운영 정책이 아니라 시스템 규칙에 해당하므로 UI에 노출하지 않는다.

- 대기 등록 시 선차감 방식
- 지각 취소는 차감만 하고 노쇼 카운트에 포함하지 않음
- 예약 정지 회원의 기존 예약 유지 및 본인 취소 허용
- 타 지점 회원 마스킹 범위
- 수강권–수업 매칭 제한
- 이용권 만료일 이후 예약 차단
- 매니저 권한의 지점 분리 및 교차 수강 예외 열람

## 8. 알림 명세

### 8.1 채널

카카오 알림톡으로 일원화한다. 라운지핏 명의 비즈니스 채널은 개설·운영 중이며 템플릿 심사만 남아 있다.

**구현 방침**: 발송부를 `NotificationSender` 인터페이스로 추상화하고, 심사 완료 전까지는 앱 내 알림함 + 발송 로그 기록 구현체로 동작시킨다. 승인 후 알림톡 어댑터로 교체한다. 심사 지연 시 SMS 어댑터를 예비 경로로 사용한다.

### 8.2 템플릿 (6종)

| 코드 | 발송 시점 | 변수 | 수신 대상 |
|---|---|---|---|
| WAIT_OPEN | 대기 순번 도래, 좌석 배정 | 회원명, 수업명, 지점, 수업일시, 확정마감시각 | 해당 대기자 1인 |
| WAIT_EXPIRED | 타임아웃으로 순번 소멸 | 회원명, 수업명, 수업일시 | 해당 대기자 1인 |
| CLASS_CANCELED | 스튜디오 사정 당일 취소 | 회원명, 수업명, 지점, 수업일시, 복구횟수 | 예약자 + 대기자 |
| CLASS_CLOSED | 인원 미달 폐강 | 회원명, 수업명, 지점, 수업일시, 복구횟수 | 예약자 + 대기자 |
| INSTRUCTOR_CHANGED | 대체 강사 투입 | 회원명, 수업명, 수업일시, 변경강사명 | 예약자 |
| BOOKING_BLOCKED | 노쇼 누적 예약 정지 | 회원명, 정지사유, 해제예정일 | 해당 회원 |

- CLASS_CANCELED / CLASS_CLOSED는 대기자에게도 발송하며, 대기자용은 복구 문구를 대기 기준으로 치환한다.
- 심야 정지 구간에는 WAIT_OPEN을 발송하지 않는다.
- 모든 발송은 `NotificationLog`에 기록하고 실패 시 재시도 대상으로 표시한다.

## 10. 개발 우선순위

### Phase 1 — 코어 (예약 정합성)

인증, 회원·이용권 데이터 시드, 시간표 조회, 예약·취소, TicketUsage 원장, 정원 초과 차단, 수강권 매칭, 일·주 한도, 만료일 차단

### Phase 2 — 대기열

선차감 등록, 좌석 반환 감지, 순차 배정, 타임아웃 스캐너(30분/10분), 심야 정지 및 재개

### Phase 3 — 백오피스

시간표 등록, 대리 예약, 출석·노쇼 처리, 폐강, 당일 취소, 대체 강사, 예약 정지 스위치

### Phase 4 — 정책·권한·알림

정책값 설정 화면 및 검증, 지점 권한 분리·마스킹, 롤링 오픈 스케줄러, 알림 인터페이스 및 템플릿 연동, 교차 수강 통계
